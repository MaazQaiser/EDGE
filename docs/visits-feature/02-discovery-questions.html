Start here — assumptions we've locked, please challenge them

  • A runsheet is a weekday-recurring template, not a dated object. Read from POST /shiftassignment/patrol/template.
  • A hit's weekday is fixed by its site's job. So clubbing only ever groups hits already on that day.
  • Tour-less visits are skipped, not blocked — the rest of the batch still merges.
  • No cap on visits per runsheet; projected duration is the only constraint.
  • Split runsheets can't be a merge target in v1.
  • Adding to a live/started runsheet is currently assumed out of scope.

If any of these is wrong, it changes the design rather than just the code — worth five minutes at the top of the meeting.

Audience one

Delivery lead, product & ops

Business intent, contractual constraints, and the operational rules no amount of code reading will reveal.

Scope & value

  1. DL-01Who is the primary user — a dispatcher planning next week, or a supervisor reacting to today?Blocking Planning wants density and bulk actions; reacting wants status and exceptions. It changes the default view, the sort order, and whether live runsheets must be editable.
  2. DL-02What do schedulers do today instead? Spreadsheet, memory, or the existing Assign Hits page?Soon If there's a spreadsheet in the loop, its columns are the real requirements doc.
  3. DL-03How many unassigned visits actually pile up in a typical week, and at the worst site?Soon Decides whether this is a 20-row list or a 2,000-row virtualized grid. Currently guessed.
  4. DL-04Is this FilterGo-only, or does Signal get it too?Blocking The code path is shared — the API says patrol for both — so Signal exposure is nearly free, but it changes labelling, QA scope, and rollout.
  5. DL-05What does success look like in numbers — fewer unassigned visits, less planning time, better route density?Soon Determines what we instrument. Right now nothing measures this.
  6. DL-06Is a specific customer or deadline driving this?Soon A named customer usually carries the real edge cases with them.

Service cadence & contracts

  1. DL-07Is a site's visit frequency contractual, or an internal planning choice?Blocking The whole design assumes it's contractual and therefore untouchable by a scheduler. If it's soft, cross-day clubbing becomes the more valuable feature.
  2. DL-08Can a visit ever legitimately move to a different weekday? Who authorises it?Blocking This is the single assumption most likely to be wrong. Directly validates or kills decision D1.
  3. DL-09Is there a tolerance around the scheduled day — can a Monday filter change happen Tuesday without breaching anything?Soon A ±1 day tolerance would let us suggest clubbing opportunities across adjacent days without a contract change.
  4. DL-10Who owns changing a site's service cadence today, and through what screen?Later If clubbing surfaces "this would be better on Tuesday", we need somewhere to send the user.

Operational rules

  1. DL-11Is there a maximum number of visits per runsheet, or a maximum route duration?Blocking We've assumed no cap and used projected duration as the only limit. A real cap becomes a hard validation rule.
  2. DL-12What's the acceptable drive time or distance between consecutive visits?Soon Nothing currently stops someone clubbing visits 60 miles apart. Needs a warn threshold at minimum.
  3. DL-13What should happen when the target runsheet has been split across officers?Blocking Which half does a new visit join? We've blocked split runsheets as targets purely because the rule is undefined.
  4. DL-14Is pushing a route past its scheduled end time acceptable, does it need approval, or is it forbidden?Soon Decides whether overrun is a warning the user can click through or a hard block.
  5. DL-15If a route grows past a break-rule threshold, who adjusts the break rule — the system or a human?Soon Runsheets carry breakRule and a payable flag. We currently warn and change nothing.
  6. DL-16Can visits be added to a runsheet whose shift has already started today?Soon Editing a recurring template mid-execution is very different from planning next week. See also DEV-04.
  7. DL-17When a visit already sits on another runsheet, is moving it a normal action or an exception?Soon Changes whether "move" is a first-class button or something behind a confirmation.
  8. DL-18Should missed visits appear in the same clubbing flow, or stay in their own drawer?Later Missed hits are a separate entity with their own reassign path that already works.

Governance

  1. DL-19Which roles may bulk-assign visits? Same people who can edit a runsheet today?Soon We've assumed runsheets.update and runsheets.create are sufficient.
  2. DL-20Does the assigned officer get notified when visits are added to a route they already own?Soon Especially if the route is for tomorrow. No notification is currently designed.
  3. DL-21Does a merge ever need approval, or is the scheduler's word final?Later An approval step would change this from one action into a workflow.
  4. DL-22What has to be auditable — who clubbed what, when, and why?Later hitAdded / hitRemoved log actions exist. Question is whether a bulk merge is one entry or many.

Language

  1. DL-23What does FilterGo actually call these on screen — visit, hit, runsheet, route, filter change?Blocking The demo's tenant labels are Signal-only; there are no FilterGo term overrides in the codebase at all. Every string in this feature depends on the answer.
  2. DL-24Who maintains tenant labels, and are they per-customer or per-brand?Soon Labels come from an API at runtime, so someone somewhere is authoring them.

Audience two

Devs & backend

Model semantics, transactional behaviour, and the reasons behind constraints the frontend currently just obeys.

Data model & lifecycle

  1. DEV-01Confirm: a runsheet is a weekly-recurring template keyed to one dutyDay, correct?Blocking Inferred from the /template endpoint and day-of-week listing. Everything downstream rests on it.
  2. DEV-02Is a hit a materialised row, or computed on the fly from the site's job config?Blocking Determines whether we can attach state to a hit, and whether hit IDs are stable across weeks.
  3. DEV-03How far ahead are hits generated? Is there a rolling horizon?Soon Sets how far forward the planning screen can usefully look.
  4. DEV-04If I add a visit to a Monday runsheet template, does this Monday get it, or only future Mondays?Blocking The biggest unknown in the whole design. It decides whether the UI must expose a "from when" choice, as the dedicated-shift flow does with todayOnly / todayOnwards.
  5. DEV-05When does a template become an instance — what creates a shiftActivityLog, and when?Soon We need to know which layer the merge writes to and what the user sees afterwards.
  6. DEV-06What's the difference between hitUtcDay and dutyDay?Soon Both appear in payloads. A franchise near a timezone boundary could see them disagree.
  7. DEV-07What's the lifecycle of a missed hit — is missedHitId a different entity or the same hit in another state?Later visitRowIdKey treats hit, missed hit, and dispatch as interchangeable row identities.
  8. DEV-08Can one hit belong to more than one runsheet?Soon If the model permits it, "move" and "add" need different handling and duplicates become possible.

API behaviour

  1. DEV-09Is addHitToRunsheet transactional across the array, or does it apply partially?Blocking Decides whether a failed 20-visit merge leaves the user with 14 assigned and no way to tell.
  2. DEV-10What does it validate server-side — window overlap, duplicates, day mismatch, tour presence?Blocking Tells us which rules the client must enforce and which are already guaranteed.
  3. DEV-11What does it return on rejection — a per-hit error shape, or a single message?Soon A single string can't drive a per-visit error state in the confirmation UI.
  4. DEV-12Can we add a bulk eligibility endpoint taking hitIds[] + dutyDay?Soon Today's findRunsheet/{hitId}/{day} is per-hit — a 20-visit selection means 20 round trips plus client-side intersection.
  5. DEV-13Can the unassigned-hits endpoint take a date range instead of a single weekday?Soon /shift/patrol/unassigned/hits/{day} is one day. A week view needs a range or seven calls.
  6. DEV-14Who owns route optimisation — does the server reorder, or must the client send an ordered pathData?Blocking Determines whether the confirmation step shows a server-computed order or one we calculate.
  7. DEV-15What happens if pathData is inconsistent with the hits array in the same payload?Soon The two are sent together and could drift, especially with concurrent editors.
  8. DEV-16Is there optimistic locking on a runsheet? What if two schedulers merge into the same one at once?Soon Two clients each sending a full pathData will silently clobber each other.

Existing constraints

  1. DEV-17Why must a hit have a tour before joining a runsheet — is that a backend rule or just a UI convention?Blocking The frontend refuses it client-side. If the backend accepts it, our exclusion rule may be unnecessarily strict.
  2. DEV-18What's the difference between addHit and addHitToRunsheet? Both exist in different services.Soon We need to know which is canonical for this feature.
  3. DEV-19What is extraRunsheet? It maps to SCHEDULE_DUTIES.HIT in the calendar adapter.Later It appears to be the one place a hit is already a first-class calendar event — possibly a precedent to build on.
  4. DEV-20Why does editPatrolHit accept full ISO datetimes when the UI only exposes time-of-day?Soon If the backend accepts a date change, cross-day moves may already be possible — which would reopen DL-08.
  5. DEV-21Is the Overview tab's "patrolVisitsCompleted" KPI counting hits? Where does it come from?Later Suggests a visit-level aggregate already exists server-side that we might reuse.

Non-functional

  1. DEV-22What's the realistic and worst-case unassigned-hit volume per day for a large franchise?Soon Pairs with DL-03 — product's guess and the database's answer often differ.
  2. DEV-23Why is SCHEDULE_CALENDAR_VIRTUALIZATION behind an env flag? Is it production-ready?Soon If visits become rows, we will need it on.
  3. DEV-24What DST problems have already bitten here?Soon The codebase carries getCurrentTimeWithDisabledDlsInIso and dayjsWithStandardOffset, which says this has history worth hearing before we repeat it.
  4. DEV-25Is there a test or demo tenant with realistic FilterGo data we can build against?Soon The local demo's mock labels are Signal-only, so FilterGo terminology can't currently be exercised.
Ask these two first DL-08 (can a visit move weekday) and DEV-04 (does a template edit hit this week or only future weeks). Everything else is detail; those two can each invalidate the design rather than adjust it.
